# FORMIC · 蚁穴路径工作台

一个可嵌入其他功能的静态网页模块：上传图片、选择区域、传统图像分割、骨架提取、手动校正、导出路径。无运行时依赖，无 AI 模型，无第三方图片上传。

## 运行

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory dist
```

打开 `http://127.0.0.1:8765/`。使用 HTTP 服务，不能以 `file://` 双击打开，因为网页使用 ES modules 与 Web Worker。也可以将 `dist/` 放入现有网站的静态目录。

## 文件

- `dist/index.html`：单页面操作界面。
- `dist/style.css`：自适应布局。
- `dist/app.js`：页面状态、画笔、撤销、上传、导出和嵌入接口。
- `dist/engine.mjs`：独立纯 JavaScript 图像处理模块。
- `dist/worker.js`：后台线程执行计算，支持终止，避免界面冻结。
- `dist/assets/sample.jpg`：用户提供的示例图片。
- `tests/engine.test.mjs`：有针对性的拓扑与坐标测试。

## 图像处理流程

1. 根据上部亮度变化建议地表位置，可手动框选或选择全图；建议不是语义检测。
2. 读取原图像素，按最长边最多 1400 像素处理。透明区域使用白底。
3. 亮度提取、高斯抑制颗粒纹理、双边滤波、局部均值对比度增强。未实现 CLAHE，不将此方法称为 CLAHE。
4. ROI 内的 Otsu 阈值、局部亮度差与双阈值区域生长生成候选通道。默认偏向保守提取。
5. 按面积清理孤立噪点。1 像素闭运算默认关闭，避免擅自连接不同通道。
6. Zhang–Suen 骨架化，在零填充图像上处理，支持边界路径。按骨架像素邻接提取网络，合并相邻分叉像素，保留闭环、独立区域和短分支。
7. 在原图叠加检查；补画/擦除后重新计算整个图网络。撤销/重做保存最近 15 个遮罩。重新选择 ROI 或重新提取会重置校正。

参数中的最小面积、画笔直径均以处理图像素为单位。处理分辨率会显示在画布下方。小于滤波尺度的细通道可能被削弱，可降低降噪级别并手动修正。

## 集成

算法不依赖 DOM，可由其他页面导入：

```js
import { extractPaths, analyzeMask } from './engine.mjs';
const result = extractPaths({
  rgba: imageData.data,
  width: imageData.width,
  height: imageData.height,
  roi: { x: 0, y: 0, width: imageData.width, height: imageData.height },
  options: { sensitivity: 50, contrast: 1.3, denoise: 2, minArea: 50, closeGaps: false }
});
// result.mask、result.skeleton 为 Uint8Array；result.graph 包含 nodes 和 edges。
// CPU 密集调用应像本网页一样放入 Web Worker。
```

现有页面也可调用 `window.Formic.getResult()` 获取原图坐标结果，`window.Formic.getState()` 读取状态，`window.Formic.extract()` 执行当前参数的重新提取，`window.Formic.loadFile(file)` 载入文件，`window.Formic.setROI(roi)` 使用处理图坐标设置区域。提取将替换上次结果和人工修改。

页面在支持 `document.modelContext` 的浏览器注册读取结果和执行提取两个工具；当前验证环境未提供原生 WebMCP，常规网页功能不依赖该接口。

## 导出约定

- JSON：原图坐标中的节点与折线路径、ROI、缩放关系、实际用于该次识别的参数、人工修改次数，以及审阅提示。UI 参数改变但未重新提取时，导出仍对应上次已完成结果。
- SVG：原图尺寸的矢量中心线，透明背景，可继续编辑。
- PNG 遮罩：白色为通道、黑色为背景，恢复到原图尺寸，缩小时已丢失的细节无法恢复。
- PNG 叠加：原图、通道遮罩、中心线与节点。

坐标原点为左上角，折线采样采用像素中心。节点类型为 `endpoint`、`junction`、`loop`、`isolated`；`boundary` 表示区域边界附近并且遮罩延伸到边界。分叉节点同时包含 `clusterPixels`，边通过真实骨架像素连接到代表点。`lengthPx` 是折线长度之和，分叉簇内部的共享短段可能重复计入。宽度是两遍 chamfer 距离的近似估计。均不是有物理比例尺的实测值。

最多接受 25 MB、6000 万像素的源图片；为避免浏览器内存耗尽，PNG 导出限制为 2400 万像素。更大图片可导出 SVG 或 JSON。

## 验证与限制

运行 `node tests/engine.test.mjs` 验证 T 形分叉、闭环、边界出口、多区域、空输入、确定性、ROI 限制和导出图坐标连续性。真实示例和上传、画笔、撤销重做、导出、取消操作、自适应布局通过 Chromium 浏览器检查。

示例能提取主要可见暗色通道，但没有人工真值标注，因此没有经过精度评估。它不能判断被遮挡路径的真实连接、洞室内部三维结构，或自动区分所有阴影。宽洞室可能产生多个骨架分支，当前保留它们供校正，未实现洞室语义分类或 GrabCut。请结合原图复核后再用于寻路或测量。

## v2：图像支持的空间连续性重建

页面已移除「路径概览」。导出入口移动到右侧操作区。

v2 在基础分割之后加入 `dist/reconstruction.mjs`：

1. 在多个平滑尺度计算亮度 Hessian。正曲率、低切向曲率与沟槽两侧亮度支持共同形成暗沟槽响应。结合局部亮度差得到归一化的相对凹陷势场。
2. 根据骨架端点的切向、宽度、距离，提出端点之间及端点到主通道的连接候选。只在 ROI 内寻路。
3. 用 A* 寻找较低代价的路线，代价包含弱沟槽证据、亮部障碍和方向偏离。拒绝证据过弱、连续无证据区过长、绕路过多或方向不匹配的路线。
4. 将路径代价权重改变 18% 后重新寻路。路线最大偏移超过 3 个处理像素时拒绝该候选。这是启发式稳定性检查，不是独立精度验证。
5. 允许证据支持的闭环；限制补线影响范围，避免自动触碰第三个不相关区域。每个源端点最多补一条连接。
6. 重新计算骨架、节点和边。补线新像素保留 `inferredMask`，JSON 中的边和 `inferredConnections` 包含推测来源、线索评分和审阅标记。

势场不是深度测量，不含相机、光照或材质标定。照片中的暗色可能来自阴影、材质或凹陷，算法无法唯一恢复真实三维空间。凹陷图展示未经物理标定的图像线索；2.5D 视图将平滑后的势场投影为可旋转表面，仅帮助检查结构假设。未调用 AI 深度模型。

「显示推测连接」只切换显示。「沿沟槽补全断点」改变下一次提取；关闭并重新提取后完全禁用自动推测。「包含推测连接」控制本次导出：取消后从当前遮罩剔除补线像素并重新计算网络，JSON、SVG、PNG 均遵循此开关。凹陷图 PNG 是独立的图像线索导出，不受补线开关影响。推测部分在 SVG 中使用橙色虚线。

手动擦除补线不会触发自动重建。撤销/重做同时保存遮罩和推测来源。相对凹陷图支持单独导出，白色代表更强凹陷线索，黑色代表弱线索或 ROI 外。证据分数不是概率，`quality.metricDepth` 和 `quality.calibratedConfidence` 均为 `false`。

默认参数下，用户示例提出并接受 7 处连接假设；独立区域从 13 个变为 7 个，端点从 36 个变为 27 个。区域或端点减少不等于精度提高，未进行人工真值准确率评估。明显缺乏证据的断点仍保留。

验证：`node tests/engine.test.mjs`、`node tests/reconstruction.test.mjs`。新增测试包括明亮但连贯的沟槽、亮色土墙阻隔、最大连接距离、禁用补线、擦除不重连、结果确定性。浏览器验证了七个图层、2.5D 旋转、含/不含推测的导出、凹陷图 PNG，以及手机和平板布局。原生 WebMCP 仍不在当前验证环境中。

方法参考：[scikit-image 的 Hessian 多尺度线结构检测说明](https://scikit-image.org/docs/stable/auto_examples/edges/plot_ridge_filter.html)。当前实现为独立 JavaScript 代码，没有引入该 Python 库。

## v3：更换图片与保守的骨架平滑

画布标题栏和页面右上角均提供「更换图片」。两个入口共用本地文件选择器，可重复选择同一张图片；成功替换后清除旧路径与校正历史，重新选择区域并提取。取消文件选择保留当前结果。

「骨架平滑 → 转折柔和度」提供原始、轻柔、适中、较柔四档，默认轻柔；调节即时生效，无需重新分割。`dist/path-smoothing.mjs` 沿中心线弧长做局部高斯加权，固定每条边的首尾节点，限制最大位移为 1.25 / 2 / 2.75 个处理像素。逐格检查修改后的线段是否仍在通道遮罩内，越过土壤的调整回退。保留短分支、闭环、节点及连接关系，不改变二值遮罩和原始骨架。它改善局部几何外观，不代表识别准确率提高。

叠加、骨架、2.5D 和 SVG / 叠加 PNG / JSON 导出共用相同的平滑路径。JSON schema 为 2.1：`edges[].points` 是当前柔和度下的原图坐标，`rawPoints` 保留原始骨架坐标，`lengthPx` 与 `rawLengthPx` 分别对应二者；`inferredSegments[i]` 标记第 i 到 i+1 点的原始推测来源，平滑不重新推断来源。`processing.pathSmoothing` 记录档位和处理图坐标中的最大位移。设为「原始」会精确恢复未经平滑的折线；遮罩与凹陷图导出不受影响。

验证：`node tests/smoothing.test.mjs` 检查锯齿柔化、位移上限、节点固定、闭环、拓扑与推测来源保留、窄通道不穿墙、原始几何不被修改。浏览器检查两个按钮唤起文件选择、替换与重复选图、取消保留结果、示例重载、柔和度即时生效，以及导出和移动端布局。

## v4：每条主要蚁道保留一条中心线

默认「中心线整理 → 保留路径」为「主要中心线」，可即时切换「完整骨架（对照）」。本次按用户确认保留各主要蚁道及其主干分叉，不把整图压成一条最长路线。

`dist/main-paths.mjs` 在平滑之前对图网络做可逆的结果筛选：

- 按空间跨度及长度 × 宽度的支持量过滤细小孤立区域。
- 对局部小环优先去掉较窄的一侧；较大的环形通道保留。仅删除现有边，不新建跨区域连接。
- 沿叶节点追踪完整支路，按长度和连接处的通道宽度去除短刺；保留较长主干、图像/ROI 边界出口及一条由最远点测地线扫描获得的保护路线。保护路线是启发式路线，不宣称精确最长简单路径。
- 合并清理后仅有两个邻居的中间节点，让同一通道成为连续折线，随后应用 v3 的轻度平滑。端点坐标与导出节点保持一致。

完整分割遮罩、骨架、原始结果和画笔历史不被删除；切换完整骨架可检查被筛掉的细节。整理有可能移除真实的短支路，属于图像支持的结构简化，没有人工真值准确率保证。遮罩 PNG 仍导出完整分割区域；画布中心线、2.5D 线条、SVG、叠加 PNG 和 JSON 使用当前筛选结果。

JSON schema 为 2.2：`processing.pathSelection` 记录筛选方法与被删除的源边数量；合并后的边通过 `sourceEdgeIds` 关联原始边。`stats.segments`、节点、路径长度与导出中心线一致，`rawSegments`、`rawComponents`、`rawLengthPx` 保留完整原始网络的统计；每条边的 `rawPoints` / `rawLengthPx` 指筛选合并后、平滑之前的几何。`pathSmoothing.preservesTopology` 相对于已筛选图，`quality.pathTopologySimplified` 则明确本次是否使用了主线简化。推测连接证据仅输出仍与选中推测线段空间关联的候选，仍不表示经过实测的连通性。

验证：`node tests/main-paths.test.mjs` 检查短刺清除、长主干与边界入口保留、小环选择宽通道、大环保留、连续折线合并、原始图恢复与不增加连接。已有引擎、补线及平滑测试通过。浏览器验证了主线/完整骨架切换、导出一致性、换图、补画撤销重做和移动端布局。彩色示例默认参数下，输出从 36 条骨架边整理为 21 条合并中心线；灰度示例从 445 条整理为 37 条。条数减少同时包含短枝删除和线段合并，不是识别准确率。

## v5：换图后只显示中心线，重新计算洞室内部路线

每次成功载入图片（包括示例）都会恢复「主要中心线」，关闭区域填色与节点标记。默认「中心线」图层显示原图与线条；「纯线条」图层隐藏原图。区域填色仍可在局部校正面板中主动开启检查。画笔按下时只临时显示本次修改区域，松开后恢复中心线显示。

新增 `dist/center-routes.mjs`，由 Web Worker 执行：先做 v4 的主干选择，再检查非边界末端的宽度与迂曲程度，收掉纹理导致的卷曲尾端。以距离变换值构造通行代价，在原始通道遮罩内部用 A* 重新寻找偏向较宽中部的路线，然后清理缩短后的侧枝及空间范围较小的附着环。孤立的大环、较长主干和边界入口继续保留。重新寻路不扩张遮罩、不填补背景像素，人工切断仍保持断开；无法找到受约束路线时保留原路径。原始骨架仍可切换查看。路径来源按新路线重新核对推测遮罩。

近乎灰度的图片不再按亮度行突变猜测地表位置，默认保留全图，避免误截上方入口；仍可手动框选。新算法不能恢复分割阶段漏掉的亮色细通道，因此保留的断点不代表真实不连通，也没有构建真实三维结构。

导出增加「纯中心线 PNG」：透明背景、仅线条、不包含填色与节点。SVG 同样只含当前中心线。原图与中心线 PNG 使用当前辅助图层开关，默认无填色。JSON schema 为 2.3，`rawPoints` 指当前路线在轻度平滑之前的像素中心几何，不再承诺是最初骨架的采样点；原始完整网络统计仍单独保留。`pathSelection` 记录重新寻路、末端整理及后续去环信息，`maskExpanded` 为 false。

验证：`node tests/center-routes.test.mjs` 覆盖卷曲路线收敛、路线受遮罩约束、边界入口保留、土墙和人工切断不跨越、原始数据不变及灰度图入口不被裁剪。已有引擎、补线、平滑和主线筛选测试通过。浏览器在用户灰度图上检查换图后的默认显示、纯线条/原图叠加、导出透明 PNG、推测排除、画笔撤销重做和移动端布局。

## v6：多线索浅通道恢复与中心线连接

新增默认开启的「识别浅色通道」与「沟槽线索」图层。更换图片后依然默认只显示主要中心线，无区域填色和节点；修改识别开关需要重新提取。全部计算为本地纯 JavaScript，没有 AI、外部模型或图片上传。

`dist/surface-evidence.mjs` 在原有分割与骨架化之间恢复浅通道：

1. 小尺度平滑抑制颗粒，以局部高频残差估计纹理强度。
2. 在两个尺度做灰度闭运算，以附近较亮表面估计局部凹陷候选。闭运算与原亮度的差属于黑帽形态学线索，不是深度。
3. 在 12 个法向、6 个宽度上比较沟槽中部与两侧肩部，同时沿切向取样。要求两侧同时较亮，并惩罚沿线亮度变化，减弱单边阴影和孤立颗粒的响应。
4. 从已分割暗部向相邻且满足凹陷与成对肩部条件的像素生长；限制在 ROI 和有限传播距离内。先恢复连续区域，再细化中心线，因此能连接较浅、较亮的细通道。
5. 剩余短缺口仍走受证据约束的 A*：补线代价同时参考原 Hessian 和新增的成对肩部线索，保留方向、连续弱证据长度、绕路和权重扰动稳定性检查。补线像素保留推测标记，不强制把所有区域连成一个图。
6. 主线清理保护宽洞室的短终点；较大的空间环路不能仅因洞室较宽就被判为小环。洞室内重新寻路后不重复按相对体量剔除已保留的独立主要区域。

「沟槽线索」亮处表示更强的表面差异与成对肩部响应。它与原有「凹陷图」「2.5D」分开显示，三者均不是真实深度。关闭浅通道识别后，线索图为空；关闭浅通道识别和断点补全可以恢复基础分割。单张照片无法可靠分辨所有阴影、材质、遮挡或隐藏连接，未进行人工真值准确率评估。

引擎版本 2.1.0，JSON schema 2.4。`processing.parameters.detectSurface` 记录识别开关；`processing.surfaceDetection` 包含本次原始提取增加的候选像素数、恢复前后区域数与方法名。这些诊断不随手工画笔重新估计；`manualEdits` 单独记录修改次数。`directMask` 指浅通道恢复后、推测补线之前的外观分割候选。浅通道恢复也属于启发式识别，不等于物理证实；橙色推测来源专指跨缺口补线。关闭推测导出会移除这些补线并重新计算中心线，不删除已有的外观分割候选。

用户原始灰度图在默认参数下，基础分割为 23 个区域，浅通道恢复后为 2 个，最终主要中心线保留 2 个独立网络；其中左上连接包含一段橙色补线。彩色示例同样检查了土壤纹理与主通道。网络更连贯不等于连接关系已全部正确，右上部分浅连接仍需要核对与手工校正。

## v7：抑制纹理短刺，在主线上再次检查断点

本次在 v6 之上保留同一套浅通道分割，不新增 AI 或外部服务。

- 主线整理使用同一前景区域内的局部宽度估计，替代单个根部像素的宽度。搜索半径结合图像尺度和支路长度，避免颗粒造成的细缝把短刺误判为单独洞室。长且直接通向宽洞室末端的路线、图像/ROI 入口继续保留；一个洞室的所有短臂被判为碎枝时保留其主穿行路线，避免整段消失。
- 基础分割和原始骨架补线之后，在已整理、重新居中的路线端点上再检查一次断点。此时暂时保留待连接的末端，补线后再清理碎枝。端点回缩到洞室内部不会直接阻止搜索；最终候选必须满足真实缺失部分的长度限制。
- 很短的缺口增加两侧线索支持规则：缺口像素少、两侧连续性较强、表面差异可见、首尾方向一致、绕行较少，并且改变代价权重后路线偏移不超过 1 像素。原有强沟槽规则继续保留。规则评分均为启发式，不是准确率或概率。
- 对进入候选的路线，重新比较原图中部与法向两侧的局部均值。连续出现无两侧低暗关系的亮平段时拒绝补线，防止平滑把窄土壁误判成沟槽。检查只对前序规则通过的候选执行。仍不能从照片证明实际深度、遮挡结构或物理连通性。
- 「最大缺口距离」限制缺失部分的路径长度；缺失像素边缘的进出步长也计入。橙色虚线、推测排除导出、人工擦除与历史操作均保留。人工校正只重新分析当前遮罩，不运行两轮自动补线。

引擎为 2.2.0，JSON schema 为 2.5。`quality.groundTruthAccuracyValidated` 明确为 false；补线包含 `stage`（原始骨架或中心线复查）、`gapLengthPx`、`rule` 和实际计算的原图横截面检查结果。证据指标均使用处理图坐标与像素；JSON 导出的几何仍恢复为原图坐标。主线选择中增加 `postRouteRemovedSpurs` 诊断。
