# 蚁穴峡谷 Demo · 操作说明

> 网页原型在 `06_Prototypes/Ant_Garden_Web_Demo/`（2026-10-05 从 T9 复制过来，T9 上的原件没动）。下面说的"文件夹"都是指它。

## 启动

1. 双击文件夹里的 **`Start.command`**，浏览器会自动打开 `http://127.0.0.1:8770/`。
   - 弹出的终端窗口要一直开着；用完在终端里按 `Control + C` 关闭。
   - 第一次双击如果 macOS 提示"无法打开"，就右键点它，选"打开"。
   - 运行时需要联网，因为 Three.js 和 Spark 这两个 3D 库是从网上加载的。
2. 屏幕上会出现"正在生长峡谷"的进度条，大约 5–15 秒后蚂蚁出现，就可以开始操作。

## 操作

| 按键 | 作用 |
|---|---|
| `W` / `↑` | 向前爬（方向以镜头朝向为准） |
| `S` / `↓` | 往回爬（蚂蚁会先转身） |
| `A` / `←`、`D` / `→` | 向左、向右爬 |
| 按住 `Shift` | 快跑（起步更快，转弯不掉速，镜头视野会拉宽） |
| 鼠标左键拖动 | 转动镜头 |
| 鼠标滚轮 | 拉近 / 拉远镜头 |
| `空格` | 停下时做触角动作 |
| `E` | 靠近其他蚂蚁时和它碰碰触角；走到发光圆环（故事物件位）旁边时打开说明；走到出口光门前时前往相邻模块 |
| `M` | 打开模块地图：**点地图上任意位置，蚂蚁就传送过去**（点到墙里会自动吸附到最近的可走位置）；地图下方第一排按钮是"洞室 / 物件位 / 出口"，点一下直接传送到那里；第二排按钮去 001–013 任意模块；`Esc` 或再按 `M` 关闭 |
| `P` | 切换"粒子显示"：每个高斯点画得更小，整个场景变成一颗颗发光的粒子（会记住你的选择） |
| `H` | 隐藏 / 显示左上角的说明 |

和常见的第三人称游戏一样：按方向键时，蚂蚁会先转向那个方向再往前爬。松开鼠标约 1.5 秒后，镜头会自己转回蚂蚁身后。

蚂蚁只能在峡谷底部走，碰到两侧的苔藓陡坡、六边形边框、路边的植物和其他蚂蚁都会被挡住。

**其他蚂蚁**：Ant_002（大个的蓝色蚂蚁）和 Ant_003（带翅膀的飞蚁）会沿着路径自己走动。你走近时它们会停下来转向你、碰触角。Ant_003 时不时会起飞，飞过峡谷再落回路上。你操作的 Ant_001 脚下有一圈淡淡的光，身体边缘也有一点微光，用来区分。

## 模块与六边形边框

- 每个模块都是 `04_Paths/Images` 里的一张路径图，用 Path Recognize 识别后，框在一个正六边形里。六边形会自动放大到能装下所有分叉和环路。
- 每条路宽窄不同（通道宽约 8–14 个单位，有的地方会收窄），路径交汇处是大的洞室（半径 10–18），洞室里有水洼和发光植物。照片里本来就更粗的路，在场景里也会更宽。
- 峡谷通到六边形边缘的地方有一道**出口光门**。走到门前按 `E`，会前往下一个模块。
- 左上角"路径"菜单可以直接选模块 001–013。默认打开模块 013。

## 拼接：两到三个蚁穴连成一片

左上角"路径"菜单里的"拼接（多个六边形）"有三个现成的组合：

| 选项 | 排法 |
|---|---|
| 拼接 010 + 013 | 两个六边形左右相连 |
| 拼接 006 + 010 + 013 | 三个六边形排成一排 |
| 拼接 001 + 002 + 003 | 三个六边形品字形排列 |

拼接是怎么做的：

1. 所有蚁穴先统一成同样大小的六边形，相邻的两个共用一条边。
2. 每个蚁穴可以按 60° 一档旋转。程序会把所有旋转组合都试一遍（三个蚁穴是 36 种），挑一个让两边通道在共用边上对得最准、悬空的通道最少的组合。
3. 对上的两条通道，用一条平滑的 S 形"接口通道"连起来，接缝处比两头稍宽一些。
4. 某条共用边上如果只有一边有通道，就从这条通道分一个岔，接到对面最近的路上；两边都没有通道时，在两个蚁穴最靠近的两段路之间开一条通道。所以每条共用边都一定走得过去。
5. 没接上的通道尾巴会在本蚁穴内收成一个尽头洞室；只有通到最外圈边缘的通道才是出口。

走过接缝进入另一个蚁穴时，屏幕上方会出现"蚁穴 0xx · 第几个蚁穴"。在地图上，外圈边框是亮线，蚁穴之间的接缝是淡线。

拼接后的世界有原来的两到三倍大，所以装饰物会按蚁穴数量自动摆得稀一些，保证整个场景的 splat 总量在 7000 万左右以内。

## 画面上有什么

- **左上**：选择模块（001–013）或示例路径，也可以调画质（低 / 中 / 高）。改完页面会重新生成。
- **右上小地图**：六边形是模块边框，浅色是可以走的峡谷底，细线是识别出的路径，黄圈是故事物件位，青色圆点是出口，箭头是蚂蚁的位置和朝向。
- **左下**：帧率和 splat 数量，方便判断电脑跑不跑得动。
- **发光圆环**：故事物件位。走近会提示"按 E"，以后用户上传的物件会放在这里。

## 换成你自己的蚁穴

1. 用 Path Recognize 识别一张蚁穴图，导出 network JSON。
2. 把这个 JSON 文件直接拖进 Demo 窗口，峡谷会按新的路径重新生成。
3. 想换回示例，在左上角"路径"里重新选就行。

## 卡顿时

- 左上角画质改成"低"。
- 把浏览器窗口缩小一些。

场景只画镜头看得见、而且离得不太远的物件（左下角"可见物件 200/1300"就是这个意思），远处的物件还会自动降低精度。中画质下每帧最多渲染约 200 万个 splat。

加载时切到别的标签页也没关系，峡谷会在后台继续生成。

## 换成高精度素材（概念图 → 泼溅）

1. 按 `concept/PROMPTS.md` 里的提示词出图（Codex 或其他工具都行）：一张图只放一个完整物件，浅灰纯色背景，不要投影。
2. 按 `concept/assets.json` 里的文件名保存到 `concept/` 文件夹，例如 `env_fan_tree_01.png`。
3. 在本目录运行：`python3 tools/build_assets.py`。
4. 刷新 Demo。同类的代码生成素材会被替换，新素材会自动正面朝向路径摆放。
5. 想单独检查某个素材的立体效果，可以打开 `http://127.0.0.1:8770/viewer.html`。

转换在本机完成，不上传任何图片，也不调用付费服务。

## 目前的限制

- 高精度素材已经改成立体重建（茎是圆管、泡是球、树干是圆柱、几根茎前后错开），但形状是从一张正面图推出来的。要做到完全准确，还需要正面加侧面的设定图（见 `concept/PROMPTS_v3_sheets.md`）。
- 场景里的 splat 实例总量接近 1 亿时，渲染器会直接不画。加素材或放大模块时，注意左下角的"场景实例合计"不要超过约 7000–8000 万。
- 还没有放入高精度素材图之前，场景使用代码生成的通用素材（照概念图 01–04）。
- 故事物件位现在只是占位：靠近会出现提示，按 E 能打开说明，但里面还没有真正的物件。
- 只测试过 Mac 上的 Chrome 内核浏览器，用键盘加鼠标操作，还没有做触屏。

## 给开发者

| 文件 | 作用 |
|---|---|
| `src/config.js` | 所有可调参数：路径宽度、素材密度、摆放间距、画质、雾、蚂蚁速度、镜头 |
| `src/pathfield.js` | 把识别出的路径变成峡谷：距离场（碰撞）和地面高度 |
| `src/splat-assets.js` | 通用素材生成器：孔洞巨树、苔藓丘、发光孢子、扇菌、霜蕨 |
| `src/world.js` | 把素材沿路径复制、旋转、缩放、变色后摆放，生成地面、陡坡、六边形剖面、雾、故事物件位和出口 |
| `tools/convert-paths.mjs` + `prepare_paths.py` | 用 Path Recognize 把 `path image` 里的路径图批量识别成 JSON |
| `tools/image_to_splat.py` + `build_assets.py` | 把概念图转换成高精度泼溅素材 |
| `viewer.html` | 单个素材查看器 |
| `src/ant.js` | 蚂蚁的移动、碰撞和动作切换（待机 / 爬行 / 快跑 / 触角） |
| `src/camera-rig.js` | 跟随镜头，会避开墙和物件 |
| `src/npc.js` | 其他蚂蚁：沿路径走动、停下打招呼、Ant_003 起飞和降落 |
| `src/stitch.js` | 把 2–3 个六边形蚁穴拼成一个世界：旋转组合搜索、接口通道 |
| `src/bigmap.js` | 模块地图和传送 |
| `src/fx.js` | 传送光效、快跑时的孢子、植物摆动 |
| `tools/sheet_to_splat.py` | 用正面 + 侧面设定图雕出立体泼溅素材 |
| `tools/mesh_to_splat.py` | 把 3D 模型（GLB，例如 Tripo 生成的）转成泼溅素材 |
| `tools/tripo.mjs` | 调用 Tripo API：查余额、图片生成 3D 模型 |
| `assets/ant_001.glb` | Ant_001 转成的网页格式模型 |

不想双击启动的话，也可以在本目录运行 `node serve.mjs --open`。

## 用 Tripo 把概念图变成 3D 模型

1. 在 Tripo 网站的 API 页面创建一个 API key。
2. 用文本编辑器打开 `.secrets/tripo_api_key.txt`，把 key 粘进去（只粘这一行），保存。这个文件不会被分享，也不要把 key 发到聊天里。
3. 查余额：`node tools/tripo.mjs balance`
4. 生成一个模型：`node tools/tripo.mjs image concept/front/fan_tree.png concept/3d/fan_tree.glb`
   （`concept/front/` 里是从 5 张 v3 设定图裁出来的正面图：扇菌树、霜蕨卷、海绵丘、孢子柱、孔洞树干。）
5. 转成场景素材：在 `concept/assets.json` 里加一条 `"mesh"` 条目，运行 `python3 tools/build_assets.py`，再刷新 Demo。

每次生成都会记在 `concept/3d/tripo_log.jsonl` 里（任务号、用了多少点数）。
