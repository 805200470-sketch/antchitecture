# 1 · 从装置到资产与动画

蚂蚁在装置里挖出的通道，经过下面这几步，变成游戏里的峡谷、植物、蚂蚁和动画。前两步是"转译"：把真实的通道变成数据。第三、四步由程序在每次打开游戏时现场完成。第五、六步是美术资产，做好一次就放进 Unity。

```
装置（真实蚁穴）
  → ① 路径线稿 → ② 路径网络（JSON）          …… 把真实通道转成数据
  → ③ 峡谷世界 → ④ 场景内容                   …… 打开游戏时由程序现场生成
  → ⑤ 美术资产（概念图 → 3D 模型 → Unity）
  → ⑥ 蚂蚁模型与动画
  → ⑦ 光、声音和氛围
```

## 每一步的要点

### 0 → 1 装置到线稿（待补充）

这一部分目前只有结果（13 张线稿），没有过程记录。请负责装置的同学补上：装置的照片和尺寸、蚂蚁挖了多久、怎么从装置得到线稿（拍照后描线？扫描？）。照片放 `01_References/Photos/`，说明写在这一节。

### 1 → 2 线稿到路径网络

- Path Recognize 在浏览器里运行，在 `04_Paths/Path_Recognize_Package/`。它从线稿里识别出通道的中心线、分叉点和宽度，导出 JSON。
- 网页原型里还有一个批量脚本 `06_Prototypes/Ant_Garden_Web_Demo/tools/convert-paths.mjs`，可以在本机一次识别全部线稿。
- 加一个新蚁穴：线稿放 `04_Paths/Images/` → 识别 → JSON 改名 `path-014.json` → 复制到 `StreamingAssets/Paths/` → 写进 `GameConfig.cs` 的 `defaultWorld`。

### 2 → 3 网络到峡谷

- 每条通道变成一条峡谷：谷底能走，两侧是土坡，坡顶以上是高地。路口变成圆形的洞室。
- 宽窄由 `Scripts/Core/PathConfig.cs` 决定（`FixedWidth`、`ChamberMin` / `ChamberMax` 等）。两处遗迹的通道在这个基础上再乘 `GameConfig.cs` 的 `ruinWidth`（现在是 0.55，像隧道）。
- 世界由哪些蚁穴组成、怎么排：`GameConfig.cs` 的 `defaultWorld`。现在是 15 格的蜂巢：13 个蚁穴加 2 处遗迹。
- `Scripts/Core/` 是网页原型（`06_Prototypes/Ant_Garden_Web_Demo/src/`）的 C# 移植，两边算出的结果逐位相同。改了 Core 必须跑 `Tools/core_tests/run_tests.sh`。

### 3 → 4 峡谷到场景内容

- 植物按 `GameConfig.cs` 的 `scatter.rules` 摆放：离峡谷边多远（`dMin` / `dMax`）、间距、高度、成簇程度。
- 两处遗迹的物件沿主隧道排开，从玩家进来的方向一路走到尽头的"核心"（琥珀神龛 / 纽扣广场）。引路光点沿这条路线撒开，路线两侧的植物会自动让开，留出一条踩出来的小路。
- 不同蚁穴拼接的地方，两边的土色互相渗透成斑块，上面有缓缓升起的光粒，不再画一条线。

### 5 美术资产

- 出图风格：简洁、克制，细节只放在视觉焦点，避免"AI 感"。提示词在 `02_Concepts/Prompts/`。
- 地面贴图和新植物先出审核图，确认后再放进游戏。
- Tripo 要花点数，生成前先说清楚要做几个、花多少点。

### 6 蚂蚁与动画

- 五种蚂蚁（Ant_001 到 Ant_005）的设定在 `01_References/Ants/`，交付的设定不要改；新蚂蚁另建 `Ant_006/`。
- 游戏里默认用原版动画片段（腿不抽搐）。程序腿的开关在 `GameConfig.cs` 的 `ant.proceduralLegs`。
- NPC 按蚁群算法走：每个蚁穴最大的洞室是巢，路的尽头是食物点，信息素多的路线会变成"蚂蚁大道"。

### 7 光、声音、氛围

- 每个蚁穴的风格（蓝色腐海 / 琥珀）决定它的地面、植物、蚂蚁、雾和天空的颜色，在 `GameConfig.cs` 的 `biomes`。
- 走进遗迹隧道时画面会稍微变暗（约 15%），出来再恢复：`atmosphere.tunnelAmbient` 等几项。
- 音效（脚步、碰触角、铃声、环境声）全部由 `Sfx.cs` 合成，试听文件在 `Docs/音效试听/`。暂时没有背景音乐。
